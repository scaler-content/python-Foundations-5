01 · the idea

What if we need the same logic more than once?

By now you know variables, data types, operators, conditions, and loops. But in a larger program, the same piece of logic often needs to run again and again in different places.

🔮 Before you reveal: if you needed to display the same message in 20 different places in your program, would you copy-paste print() 20 times?
print("Welcome to Python!")
print("Welcome to Python!")
print("Welcome to Python!")

Repeating the same line works, but it doesn't scale — and if the message ever changes, you'd have to update it everywhere. This is exactly the problem functions solve.

Mental modelA function is a small machine: give it something → it processes it → it possibly hands something back.
def welcome():
    print("Welcome to Python!")

welcome()
welcome()
welcome()
✅ TakeawayA function is a reusable block of code that performs a specific task, written once and used wherever you need it.

03 · defining vs. calling

Does anything happen just from defining it?

🔮 Predict before revealing: if you run only this definition — no call anywhere — does anything print?
def greet():
    print("Hello!")

Nothing is printed yet. Defining a function is like drawing a blueprint — it describes what should happen, but nothing runs until you actually use it.

To make the code inside actually run, you have to call the function:

greet()

Hello!
✅ TakeawayDefining a function only creates the plan. The code inside only runs when the function is called.
04 · function flow

The life of a function call

Define Function ↓ Function exists ↓ Call Function ↓ Python executes the function body ↓ Function ends
✅ TakeawayA function exists as soon as it's defined, but it only runs — start to finish — each time it's called.
05 · parameters & arguments

Giving a function information

A function becomes far more useful when we can hand it information instead of hard-coding it:

🔮 Predict before revealing: what will all three calls print?
def greet(name):
    print("Hello", name)

greet("Asha")
greet("Rahul")
greet("Priya")

Hello Asha
Hello Rahul
Hello Priya

name is a parameter — the variable listed in the function's definition. "Asha" is the argument — the actual value supplied when the function is called.

The same idea extends to multiple parameters, matched to arguments by position:

def introduce(name, age):
    print("My name is", name)
    print("I am", age, "years old.")

introduce("Asha", 20)

My name is Asha
I am 20 years old.
✅ TakeawayParameter = the variable name in the definition. Argument = the actual value given at the call. With multiple parameters, values are assigned in order.
06 · functions + everything else

Functions don't replace what you already know — they organize it

A function can contain any of the concepts from earlier classes:

ConceptInside a function
Variablesdef square(number): result = number * number; print(result)
Operatorsdef add(a, b): print(a + b)
Conditionsdef check_age(age): if age >= 18: print("Adult") else: print("Minor")
Loopsdef print_numbers(): for i in range(1, 6): print(i)
✅ TakeawayA function doesn't replace variables, operators, conditions, or loops — it gives you a way to package them into a reusable piece.
07 · the return statement

Printing something and returning something are different

def add(a, b):
    print(a + b)

result = add(10, 20)

This displays the answer — but what if we want to use that answer somewhere else in the program? We need the function to hand the result back. That's what return does:

def add(a, b):
    return a + b

result = add(10, 20)
print(result)

30
✅ Takeawayreturn sends a value back to whoever called the function, so it can be stored and reused.
08 · print() vs. return — the vote

This is the single most common real-world bug beginners write

What will result end up as?

def add(a, b):
    print(a + b)

result = add(10, 20)

print(result)

💬 The output is:

30
None

add(10, 20) prints 30 — but that print() happens inside the function, purely as a side effect. The function itself never uses return, so it hands nothing back to whoever called it. Python's default answer for "what does this function give back?" is None. So result doesn't hold 30 — it holds None, and that's what the second print() shows.

Avoid thinking "return prints the result." Instead: print() is for the human watching the screen; return is for the rest of your program to use.

🤖 AI momentIf you guessed 30, paste this into a general-purpose AI assistant: "I expected result to be 30 here, but it's None. Walk me through exactly why, step by step." Then independently verify by adding return a + b to the function yourself, re-running it, and confirming result now holds 30 instead of None.
09 · return unlocks reuse

A returned value can be used, not just displayed

🔮 Predict the output before revealing
def square(number):
    return number * number

x = square(5)
print(x)

25

Because square() returns a value, it can be used directly, or even inside a larger calculation:

print(square(5))

25
result = square(5) + 10
print(result)

35
🔮 Three lines are inside this function. How many actually run?
def test():
    print("Start")
    return 10
    print("End")

test()

Start

Only two — the third is unreachable. As soon as Python reaches return, the function finishes immediately. "End" is never printed because the function has already returned.

✅ TakeawayA returned value can be stored, printed, or used inside another expression. return also exits the function immediately — any code after it never runs.
10 · functions without return

Not every function needs to hand something back

def greet(name):
    print("Hello", name)

This is perfectly valid — the function performs an action but doesn't explicitly return a useful value. The rule of thumb: use print() when the goal is to display something; use return when the result needs to be used elsewhere.

11 · scope: local vs. global

Where can a variable actually be accessed?

🔮 message was created while greet() ran — will it still be around once the function finishes?
def greet():
    message = "Hello"

greet()

print(message)

NameError: name 'message' is not defined

message is a local variable — created inside the function, it normally exists only within that function, and disappears once the function ends.

🔮 Unlike the previous example, will this work or fail? What's different this time?
name = "Asha"

def greet():
    print(name)

greet()

Asha

This works. name is a global variable — created outside any function — and a function can read a global variable even though it can't read another function's local one.

Outside Function ↓ Global Scope │ │ can be accessed ↓ Function Inside Function ↓ Local Scope ↓ Usually available only inside function
✅ TakeawayFor this course: prefer local variables inside functions whenever possible, instead of creating many global variables — global variables can make larger programs harder to understand and maintain.
12 · default arguments

Give a parameter a fallback value

🔮 We didn't give this function anything at all — will it error, or does it have a fallback?
def greet(name="Student"):
    print("Hello", name)

greet()

Hello Student

But you can still provide a value, and it replaces the default:

greet("Asha")

Hello Asha
Argument provided? │ ┌───┴───┐ Yes No ↓ ↓ Use given Use default value value

Default arguments make functions more flexible:

🔮 Only one value is given, but the function needs two. What fills in the gap?
def power(number, exponent=2):
    return number ** exponent

print(power(5))

25
print(power(5, 3))

125

The default exponent (2) fills the gap when it isn't supplied; a provided argument always replaces the default.

✅ TakeawayA default argument (name="Student") is used automatically when no value is supplied, but any value you do pass in overrides it.
13 · keyword arguments

Matching by name instead of position

So far, arguments were supplied by position. You can also name the parameter you're filling in:

def introduce(name, age):
    print(name, age)

introduce(name="Asha", age=20)
🔮 The order looks flipped compared to the definition — will Python still match them correctly, or will name and age get swapped?
introduce(age=20, name="Asha")

Still correct — because keyword arguments are matched by name, not position, Python knows exactly which value belongs to which parameter regardless of order.

PositionalKeyword
introduce("Asha", 20) — matched by orderintroduce(name="Asha", age=20) — matched by name

The two can also combine with defaults:

def greet(name, message="Welcome"):
    print(message, name)

greet("Asha")
greet("Asha", "Good morning")
greet(name="Asha", message="Good evening")

Welcome Asha
Good morning Asha
Good evening Asha
✅ TakeawayPositional arguments depend on order; keyword arguments depend on parameter names — and the two can be mixed with default arguments.
14 · lambda functions

A compact way to write a small function

Python also lets you create very small functions in a single line — these are lambda functions:

🔮 This function is just one expression: return x * x. Does Python have a shorter way to write something this small?
def square(x):
    return x * x

square = lambda x: x * x

print(square(5))

25
lambda ↓ Create a small anonymous function x ↓ Parameter : ↓ Separates parameter from expression x * x ↓ Expression/result
🔮 Predict the output before revealing
add = lambda a, b: a + b

print(add(10, 20))

30
Normal function (def)Lambda
Can contain multiple statementsDesigned for a single expression
Usually easier to read for larger logicUseful for short functions
Can have a descriptive function nameOften used for short, temporary operations
🤖 AI momentOnce you have both a def and a lambda version of square, ask an AI assistant: "When would a professional Python developer actually choose one over the other?" Then try rewriting the even/odd checker from the practice section below as a lambda, and judge for yourself whether it's actually more readable than the def version.
✅ TakeawayUse lambda mainly for small, simple functions where a full def would be unnecessary. For larger or more complex logic, a normal function is usually clearer.
15 · putting it together

Practical example: student score

def calculate_average(score1, score2, score3):
    total = score1 + score2 + score3
    average = total / 3
    return average

average = calculate_average(80, 90, 70)
print("Average:", average)

Average: 80.0
🔮 Now add a condition — predict both lines of output
def check_result(average):
    if average >= 40:
        return "Pass"
    else:
        return "Fail"

average = calculate_average(80, 90, 70)
result = check_result(average)

print("Average:", average)
print("Result:", result)

Average: 80.0
Result: Pass

Notice what happened: variables, operators, conditions, and functions all working together. Good programs are often built from small functions, each with one clear responsibility:

Student Program │ ┌───────────┼───────────┐ ↓ ↓ ↓ calculate check display average result result │ │ │ └───────────┴───────────┘ ↓ Final Program
✅ TakeawayFunctions let you divide a program into meaningful tasks instead of one large block of code.

17 · debug clinic

Two gotchas unique to functions

🔮 Debug 1: what does message actually hold here?
def greet():
    print("Hello!")

message = greet

Diagnosis: notice the missing parentheses — this assigns the function object itself to message, not the result of calling it. Nothing errors, and nothing prints, because greet was never called. This is one of the sneakiest kinds of bug: it runs without crashing, but does the wrong thing.

🤖 AI momentWrite your own diagnosis first, confirm the actual (odd, non-crashing) behavior by running it, then ask an AI assistant: "Why does message = greet print something like <function greet at 0x...> instead of running the function?" Compare its explanation to your own. Then apply the fix — add the parentheses — and re-run to confirm message now holds the function's actual output.

🔮 Debug 2: why does this raise a NameError?
def calculate():
    result = 10 + 20
    return result

calculate()
print(result)

NameError: name 'result' is not defined

Diagnosis: result is a local variable — it exists only inside calculate() and disappears once the function returns. To use the value outside, capture the return: result = calculate().

Debug habitBefore changing code, predict what the function is doing, check whether a value was actually called or returned, then test the smallest change that could fix it.
18 · tracing

Trace before you run

🔮 What are the parameters? The arguments? The value of total? What does the function return? What finally prints?
def calculate(x, y):
    total = x + y
    return total * 2

result = calculate(5, 3)

print(result)
calculate(5, 3) ↓ x = 5 y = 3 ↓ total = 5 + 3 ↓ total = 8 ↓ return 8 * 2 ↓ 16 ↓ result = 16 ↓ print(result) ↓ 16

Final output: 16. Parameters: x, y. Arguments: 5, 3.

✅ TakeawayTracing a function call step by step — arguments in, body executes, value returned, then used — is a core skill for reasoning about code without always running it.
